Chunking Strategies
Fixed-size: character count + overlap — simple baseline
Recursive character splitter: paragraph → sentence → word hierarchy
Semantic chunking: split at embedding cosine similarity drops
Sentence-level: spaCy / NLTK sentence boundary detection
Markdown/HTML-aware: respect headings, code blocks, lists
Parent-child: index small children, store large parent for context
Proposition-based: extract atomic factual statements as chunks
Contextual chunk enrichment: prepend document title + section header
Chunk size tuning: 256 vs 512 vs 1024 tokens — domain-specific guidance
Overlap tuning: 10–20% overlap to prevent boundary information loss
Retrieval Techniques
Top-k: retrieve k most similar chunks — tuning for recall vs precision
Similarity threshold: only retrieve above confidence score
Maximum Marginal Relevance (MMR): balance relevance with diversity
HyDE (Hypothetical Document Embeddings): generate fake answer, search with it
Multi-query retrieval: generate 3–5 query variants, merge deduplicated results
Step-back prompting: abstract the query to retrieve broader context
Query decomposition: break compound questions into atomic sub-queries
FLARE: forward-looking active retrieval during generation
Contextual compression: extract only relevant sentences from retrieved chunks
Re-ranking: cross-encoder (Cohere Rerank, BGE-Reranker) over top-20
Reciprocal Rank Fusion (RRF): combine multiple ranked lists
Advanced RAG Architectures
Speculative RAG: generate draft answer → use as retrieval query
Corrective RAG (CRAG): grade retrieved docs, web-search fallback if poor
Self-RAG: LLM decides when to retrieve, grades its own output
Adaptive RAG: route queries to RAG or direct answer by complexity
Graph RAG: knowledge graph + vector retrieval for relational reasoning
