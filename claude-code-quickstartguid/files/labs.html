Hands-on Lab Exercises

Beginner Labs

1
First Session — Explore an Unknown Codebase
⏱ 15 min · Difficulty: Beginner · Module: 1, 2

Objectives

  • Install Claude Code and authenticate
  • Launch your first interactive session
  • Use Claude to understand an unfamiliar project
  • Practice the /help and /status commands

Instructions

  1. Set up a sample project

    Clone this starter repo or use any existing project you have:

    bash
    git clone https://github.com/gothinkster/realworld-example-apps
cd realworld-example-apps
# Or use any Node.js/Python/etc project you have
  2. Launch Claude Code
    bash
    claude
  3. Ask Claude to explain the project

    Type this prompt and observe how Claude reads files:

    prompt
    Scan this project and give me:
1. What does this app do?
2. What's the tech stack?
3. What are the 5 most important files I should read first?
4. How do I run it locally?
  4. Explore the tool calls

    Notice how Claude uses Read, Glob, and Grep tools automatically. Watch the tool calls appear in the output.

  5. Try these session commands
    session commands
    /help          # See all available commands
/status        # Check model and context usage
/cost          # See token usage so far
Ctrl+C         # Exit
💡 Solution Hint

Claude should read package.json, README.md, and scan the top-level directory structure. If it doesn't do this automatically, prompt: "Please read the package.json and README.md first."

2
Create and Optimize Your CLAUDE.md
⏱ 20 min · Difficulty: Beginner · Module: 4

Objectives

  • Use /init to auto-generate a CLAUDE.md
  • Understand what /init creates
  • Customize it with real project conventions
  • Test that Claude uses the CLAUDE.md in a new session
  1. Generate a CLAUDE.md with /init
    session
    /init

    Claude will scan your project and write an initial CLAUDE.md. Review what it generated.

  2. Add your own rules

    Open the CLAUDE.md file and add at minimum:

    • A coding convention rule (e.g., "always use TypeScript strict mode")
    • A testing requirement (e.g., "all functions must have unit tests")
    • A "DO NOT" rule (e.g., "never use var, always use const/let")
  3. Test it in a fresh session
    bash
    claude   # Start a new session

# Then ask:
# "Write a utility function that formats a phone number.
#  Follow all conventions in CLAUDE.md."

    Verify Claude follows the conventions you specified.

💡 Solution Hint

If Claude doesn't follow your CLAUDE.md rules, try being more explicit: "You must follow the rules in CLAUDE.md. Please re-read CLAUDE.md and then rewrite this function." If rules still aren't followed, check that the CLAUDE.md is in the project root (same directory where you run claude).

3
Bug Hunt — Find and Fix a Bug End-to-End
⏱ 25 min · Difficulty: Beginner · Module: 1, 3

Objectives

  • Introduce Claude to a bug description and let it find the root cause
  • Have Claude implement a fix
  • Have Claude write a regression test
  • Practice the "describe → find → fix → test" workflow
  1. Pick a real bug or create one

    If you have a real project, describe a known bug. Otherwise, create this intentional bug in a JS file:

    javascript — intentional bug for practice
    // utils/discount.js
function applyDiscount(price, discountPercent) {
  // BUG: should be (discountPercent / 100), not discountPercent
  return price - (price * discountPercent);
}

module.exports = { applyDiscount };
  2. Report the bug to Claude
    prompt
    Bug report: When applying a 10% discount to a $100 item,
the final price shows as -$900 instead of $90.

The discount function is somewhere in the utils directory.
Please:
1. Find the bug
2. Explain why it happens
3. Fix it
4. Write a test that would catch this in future
  3. Observe the tool calls

    Watch Claude use Grep/Glob to find the file, Read to examine it, Write/Edit to fix it, and Bash to run the test.

💡 Solution Hint

The fix is changing price * discountPercent to price * (discountPercent / 100). A good test case: expect(applyDiscount(100, 10)).toBe(90). If Claude doesn't write the test automatically, explicitly ask: "Now write a Jest test for this fix."

Non-Interactive Mode — Scripted Tasks
⏱ 15 min · Difficulty: Beginner · Module: 3

Objectives

  • Use claude -p for non-interactive tasks
  • Capture output to a file
  • Use JSON output format
  • Pipe input to Claude Code
  1. Run a simple task non-interactively
    bash
    claude -p "List all JavaScript files in src/ and their sizes" > file-list.txt
cat file-list.txt
  2. Try JSON output format
    bash
    claude -p "Count lines of code in each file in src/" \
  --output-format json | jq '.result'
  3. Pipe code to Claude for explanation
    bash
    cat src/auth/jwt.ts | claude -p "Explain this code in 3 sentences"
  4. Restrict tools for safe read-only mode
    bash
    claude -p "Find all TODO comments" \
  --allowedTools Read,Grep,Glob \
  --max-turns 5

5
Build Your Slash Command Library
⏱ 30 min · Difficulty: Intermediate · Module: 5

Objectives

  • Create 3 custom slash commands for a real workflow
  • Use the $ARGUMENTS variable for dynamic commands
  • Use shell command injection (!`command`) in a command file
  • Verify commands appear in /help autocomplete
  1. Create the commands directory
    bash
    mkdir -p .claude/commands
  2. Create a /commit command

    Write .claude/commands/commit.md that generates a conventional commit message from the current diff. Include !`git diff --cached` to inject the diff.

  3. Create a /review command

    Write .claude/commands/review.md that takes an optional focus area via $ARGUMENTS and performs a structured code review of the last commit.

  4. Create a /explain command

    Write .claude/commands/explain.md that takes a file path as $ARGUMENTS and explains what the file does to a new developer joining the team.

  5. Test all three commands
    session
    /help                          # Verify commands appear
/commit                        # Test commit message generation
/review security               # Test review with argument
/explain src/auth/jwt.ts       # Test explain with file path
💡 Solution Hint

For the commit command: use allowed-tools: Bash(git *) and model: claude-haiku-4-5-20251001 (it's cheap and fast for this). For the explain command: use allowed-tools: Read only — no need for Bash or Write.

Full Feature Implementation with TDD
⏱ 45 min · Difficulty: Intermediate · Module: 1, 3

Objectives

  • Use a test-driven approach with Claude Code
  • Implement a complete feature across multiple files
  • Have Claude run tests and fix failures automatically
  • Practice multi-turn conversations for complex tasks
  1. Define the feature

    Pick a moderately complex feature like: "Add pagination to the users API endpoint" or "Add input validation to the registration form."

  2. Start with test requirements
    prompt (turn 1)
    I want to add pagination to GET /api/users.
Before writing any code:
1. Read the current users route and model
2. Tell me what tests we should write first (TDD approach)
3. Don't write any implementation yet
  3. Write tests first
    prompt (turn 2)
    Good. Now write the tests you described.
They should fail right now because the feature isn't implemented yet.
Run them to confirm they fail.
  4. Implement until tests pass
    prompt (turn 3)
    Now implement the pagination feature.
Run the tests after each significant change.
Don't stop until all tests are passing.

Hook Setup — Auto-Format and Notifications
⏱ 30 min · Difficulty: Intermediate · Module: 7

Objectives

  • Create a PostToolUse hook that auto-formats files after write
  • Create a Stop hook that sends a desktop notification
  • Test hooks are firing correctly
  • Understand async vs sync hooks
  1. Create the hooks directory and notification script
    bash
    mkdir -p ~/.claude/hooks

cat > ~/.claude/hooks/notify.sh << 'EOF'
#!/bin/bash
# Cross-platform notification
if command -v osascript &>/dev/null; then
  osascript -e 'display notification "Task complete" with title "Claude Code"'
elif command -v notify-send &>/dev/null; then
  notify-send "Claude Code" "Task complete"
fi
EOF

chmod +x ~/.claude/hooks/notify.sh
  2. Configure hooks in .claude/settings.json
    json
    {
  "hooks": {
    "PostToolUse": [{
      "matcher": "Write|Edit",
      "hooks": [{
        "type": "command",
        "command": "prettier --write \"${TOOL_INPUT_PATH}\" 2>/dev/null; true"
      }]
    }],
    "Stop": [{
      "hooks": [{
        "type": "command",
        "command": "~/.claude/hooks/notify.sh",
        "async": true
      }]
    }]
  }
}
  3. Test the hooks

    Start a session and ask Claude to write a file. The file should be auto-formatted. When Claude finishes responding, you should get a notification.

    prompt for testing
    Create a file called test-hooks.ts with a simple function that
adds two numbers. (Watch for the auto-format notification!)

Add an MCP Server — GitHub Integration
⏱ 30 min · Difficulty: Intermediate · Module: 6

Objectives

  • Configure the GitHub MCP server
  • Use Claude to search GitHub repos and create issues
  • Understand MCP tool naming conventions
  • Verify the .mcp.json configuration
  1. Create a GitHub Personal Access Token

    Go to GitHub → Settings → Developer Settings → Personal Access Tokens → Tokens (classic). Create a token with repo and issues permissions.

  2. Add the MCP server
    bash
    export GITHUB_TOKEN="ghp_yourtoken"

claude mcp add github \
  -e GITHUB_PERSONAL_ACCESS_TOKEN=${GITHUB_TOKEN} \
  -- npx -y @modelcontextprotocol/server-github

claude mcp list   # Verify it was added
  3. Test GitHub integration
    prompts to try
    # List your recent repos
"Show me my 5 most recently updated GitHub repositories"

# Search issues
"Search for open issues labeled 'bug' in my [repo-name] repo"

# Create an issue (use a test repo!)
"Create a GitHub issue in [your-test-repo] titled 'Test from Claude Code'
 with a description explaining it was created as an MCP integration test"

Build a Full CI/CD Integration with GitHub Actions
⏱ 45 min · Difficulty: Advanced · Module: 7

Objectives

  • Create a GitHub Actions workflow that runs Claude Code
  • Auto-generate PR descriptions using Claude Code
  • Post AI review comments on pull requests
  • Handle API key secrets securely in CI
  1. Add ANTHROPIC_API_KEY as a GitHub secret

    Go to your repo → Settings → Secrets and variables → Actions → New repository secret. Name it ANTHROPIC_API_KEY.

  2. Create the GitHub Actions workflow
    yaml — .github/workflows/claude-review.yml
    name: Claude Code Review
on:
  pull_request:
    types: [opened, synchronize]

permissions:
  pull-requests: write

jobs:
  review:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
        with:
          fetch-depth: 0

      - name: Install Claude Code
        run: curl -fsSL https://claude.ai/install.sh | bash

      - name: Run PR review
        env:
          ANTHROPIC_API_KEY: ${{ secrets.ANTHROPIC_API_KEY }}
        run: |
          DIFF=$(git diff origin/main...HEAD)
          claude -p "Review this PR for issues:
            $DIFF
            Output as Markdown with sections:
            ## Summary, ## Issues Found, ## Suggestions" \
            --allowedTools Read,Grep,Glob \
            --max-turns 5 \
            --output-format text > pr-review.md

      - name: Comment on PR
        uses: actions/github-script@v7
        with:
          script: |
            const fs = require('fs');
            const body = fs.readFileSync('pr-review.md', 'utf8');
            github.rest.issues.createComment({
              issue_number: context.issue.number,
              owner: context.repo.owner,
              repo: context.repo.repo,
              body: `## 🤖 Claude Code AI Review\n\n${body}`
            });
  3. Open a test PR and verify the comment appears

    Create a branch, make a change, and open a PR. The workflow should run and post a review comment automatically.

  5. Add 1 MCP integration

  6. Commit and document
    bash
    git add CLAUDE.md .claude/ .mcp.json
git commit -m "chore: add team Claude Code configuration"
# Push and share with your team!
