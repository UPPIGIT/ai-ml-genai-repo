Installation

Install Claude Code

One command installs the claude CLI globally. Requires Node.js 18 or higher — check yours first.

🔍
Check First
Verify Node.js
Make sure you have Node.js 18+. If not, install it from nodejs.org before proceeding.
bash
# Should be 18.x or higher node --version v20.11.0 ✓ good
⬇️
Install
Run the Installer
The install script from Anthropic handles everything — downloads the binary and adds it to your PATH.
bash
curl -fsSL \ https://claude.ai/install.sh \ | bash
Verify installation
# Verify install succeeded claude --version Claude Code v1.x.x ✓ installed # Authenticate with your Anthropic account claude auth login
✓ Success Signal
Running claude --version should return a version number. If you get "command not found", restart your terminal or add the install path to your $PATH.

Navigate to Your Project

Always start Claude Code from your project root. This gives it full context about your codebase structure.

bash

Root Directory
Run claude from the project root so it can see your entire file tree and understand the architecture.
✅
Works great
Monorepos
For monorepos, run from the top-level root. Use subfolder CLAUDE.md files to scope context per package.
❌

Don't launch from deep inside src/components/. Claude will miss important context about your full project.

Core Concept

Craft Your CLAUDE.md

CLAUDE.md is loaded at the start of every session. Think of it as Claude's briefing doc — keep it concise, specific, and actionable.

CLAUDE.md — Minimal Starter Template
# Project: My App Next.js 14 App Router + TypeScript + Postgres ## Tech Stack - Frontend: Next.js 14, Tailwind CSS, Shadcn/ui - Backend: Next.js API Routes + tRPC - DB: PostgreSQL via Prisma ORM - Auth: Clerk ## Commands npm run dev # Start development server npm run build # Production build npm run test # Jest test suite npm run lint # ESLint + Prettier check npx prisma db push # Push schema changes ## Architecture /app → Next.js App Router pages & layouts /app/api → API route handlers /components → Reusable UI components /lib → Shared utilities, db client, helpers /prisma → Schema & migration files ## Our Conventions - Use Zod for all API input validation - Prefer server components; use 'use client' sparingly - All DB calls go through /lib/db.ts — never import Prisma directly - New components get a matching .test.tsx file ## Gotchas - Local dev requires VPN for DB connection - Run `npx prisma db seed` after pulling main - The /payments module uses a legacy pattern — don't refactor without a PM review
📏
Rule
Stay Under 200 Lines
Context window attention degrades with length. Keep it tight. If it's stale, delete it. Quality beats quantity.
🎯
Rule
Be Hyper-Specific
Not "follow best practices". Instead: "use Zod for validation", "prefer server components". Exact rules, not vague guidance.
🔗
Tip
Commit to Git
Commit CLAUDE.md to your repo. Every teammate's Claude session will start with the same shared project context.

Interaction Modes

Learn the 3 Modes

Claude Code has three interaction modes. Knowing when to use each one is the single biggest productivity unlock. Switch with Shift + Tab.

Shift + Tab ×1
Normal Mode
Claude asks for your approval before each significant action. Safe and deliberate.
Shift + Tab ×2
Auto Accept
Claude executes without pausing. Use after reviewing a plan. Fast iteration.
Shift + Tab ×3
Plan Mode
Claude explains what it will do before doing anything. Review and approve first.
🎯 Best Practice Workflow
Start every task in Plan Mode → read the plan → switch to Auto Accept to execute. This gives you oversight without constant interruption. It's the gold-standard pattern for agentic tasks.
Ideal task flow example
# Step 1: Activate Plan Mode (Shift+Tab twice) [ PLAN MODE ] You: Add a password reset flow to the auth module Claude: Here's my plan: 1. Create /app/auth/reset/page.tsx — email input form 2. Add POST /api/auth/reset route — sends email via Resend 3. Create /app/auth/reset/confirm/page.tsx — new password form 4. Add token validation middleware to /lib/auth.ts 5. Update Prisma schema with PasswordResetToken model Shall I proceed? # Step 2: Switch to Auto Accept (Shift+Tab again), then confirm [ AUTO ACCEPT ] You: Yes, proceed ✓ Writing files... ✓ All 5 files created, tests passing

Keyboard Mastery

Essential Shortcuts

These eight shortcuts cover 95% of what you'll use daily. Learn them before your first real session.

Shift + Tab
Cycle through Normal → Auto Accept → Plan modes
Tab
Toggle extended thinking (deeper reasoning for complex tasks)
Esc Esc
Open rewind menu — roll back to any previous checkpoint
Ctrl + C
Interrupt a running task immediately without losing context
↑ Arrow
Navigate history — reuse or edit previous prompts quickly
Ctrl + L
Clear the current session view (history preserved)
@filename
Include a specific file in your current prompt context
/compact
Compress session when context gets long — keeps focus sharp
💡 Learn these two first
Esc Esc (rewind) and Shift + Tab (mode switch) are the two shortcuts that will save you the most time. Know them before anything else.

In Practice

Your First Real Task

Walk through a complete task end-to-end. This is the daily loop you'll use for every feature.

1
cd my-project && claude
Always launch fresh from the project root. Claude re-loads CLAUDE.md every session.
2
Switch to Plan Mode (Shift + Tab)
Before writing any code, get a plan. This prevents wasted effort and lets you catch misunderstandings early.
3
Describe your task clearly
Be specific. Include what the feature does, where it lives in the codebase, and any constraints. The more context, the better the plan.
4
Review the plan, then switch to Auto Accept
Read Claude's plan carefully. If it looks right, switch modes and confirm. If not, correct it in plain English before proceeding.
5
Commit the working result
Once Claude completes the task and tests pass, commit immediately. Small, frequent commits give you safe rollback points.
6
New feature? Start a new session
One session per feature keeps context clean. Don't let unrelated tasks pile up in the same conversation.
Writing a great prompt — example
# ❌ Vague — don't do this Add a search feature # ✓ Specific — do this instead Add a full-text search bar to the /products page. It should filter the existing product list in real-time as the user types. Use the existing ProductCard component. The search should match on product name and description. No backend changes needed — filter client-side from the data already loaded. Add a test in products.test.tsx. # ✓ With file context Review @src/components/ProductCard.tsx and add a search bar above the product grid that filters cards by name.
