MODULE 05

Slash Commands & Custom Workflows

Build reusable slash commands to automate your entire development lifecycle — from feature branches to PRs, security reviews to dependency audits.

📖 ~25 min ⚡ Automation focus

What are Custom Slash Commands?

Custom slash commands are Markdown files that define reusable prompts. When you type /command-name in a session, Claude executes the full instructions in that file. This turns repetitive, complex prompts into single-word shortcuts.

ℹ️
One File = One Command

Create a file .claude/commands/review.md → use it with /review. The filename (without extension) becomes the slash command name.

LocationScopeGit
.claude/commands/*.mdCurrent project only✅ Commit — shared with team
~/.claude/commands/*.mdAll your projects❌ Personal only

Creating Your First Commands

Basic Command Structure

markdown — .claude/commands/review.md
---
description: Perform a thorough code review of the current git diff
allowed-tools: Read, Grep, Glob, Bash(git diff:*)
argument-hint: [focus area]
---

# Code Review

Review the current git diff for:

1. **Correctness** — Logic errors, edge cases, null checks
2. **Security** — Injection risks, exposed secrets, auth bypasses
3. **Performance** — N+1 queries, unnecessary re-renders, large bundles
4. **Code Quality** — DRY violations, naming, complexity
5. **Tests** — Are new code paths covered?

If $ARGUMENTS is provided, focus especially on: $ARGUMENTS

Provide specific line-level feedback and suggest improvements.

Usage in session:

Terminal
You: /review
# Or with a focus argument:
You: /review security vulnerabilities in the payment flow

Command Frontmatter Reference

The YAML frontmatter block at the top of a command file controls its behavior.

markdown — Full frontmatter options
---
description: Short description (shown in /help autocomplete)
allowed-tools: Read, Write, Bash(git *), Grep, Glob
argument-hint: [optional: what arguments this command takes]
model: claude-haiku-4-5-20251001   # Override model for this command
---
FieldPurposeExample
descriptionShown in /help autocomplete"Security-focused code review"
allowed-toolsWhitelist tools this command can useRead, Grep, Bash(git diff:*)
argument-hintAutocomplete hint for arguments[file-or-directory]
modelOverride model for this commandclaude-haiku-4-5-20251001
💡
Use Haiku for Cheap Repetitive Commands

For high-frequency commands like generating commit messages or formatting code, set model: claude-haiku-4-5-20251001 to reduce costs dramatically while still getting good results for simple tasks.

Dynamic Arguments with $ARGUMENTS

The $ARGUMENTS variable captures everything typed after the command name. This makes commands flexible and reusable.

markdown — .claude/commands/fix-issue.md
---
description: Fix a GitHub issue by number
allowed-tools: Read, Write, Edit, Bash(git *), Grep, Glob
argument-hint: <issue-number>
---

Fix GitHub issue #$ARGUMENTS.

Steps:
1. Read the issue description from .github/ISSUES/$ARGUMENTS.md
   (or I'll describe it if you tell me)
2. Find the relevant code using Grep and Glob
3. Implement the fix following project conventions in CLAUDE.md
4. Write a test that would catch this issue in future
5. Create a descriptive commit message referencing #$ARGUMENTS
Usage
You: /fix-issue 142
# $ARGUMENTS becomes "142"

You: /fix-issue 142 focus on the mobile layout
# $ARGUMENTS becomes "142 focus on the mobile layout"

Shell Commands Inside Command Files

You can embed shell commands in your command files using backtick syntax. Claude will run these to gather context before executing the rest of the prompt.

markdown — .claude/commands/pr-description.md
---
description: Generate a PR description from the current diff
allowed-tools: Bash(git *), Read
model: claude-haiku-4-5-20251001
---

Write a GitHub pull request description for these changes:

<git_diff>
!`git diff main`
</git_diff>

<changed_files>
!`git diff --name-only main`
</changed_files>

The PR description should include:
- **Summary**: 1-2 sentences of what changed and why
- **Changes**: Bulleted list of specific changes
- **Testing**: How to verify this works
- **Screenshots**: Placeholder section if UI was changed

Follow Conventional Commits format for the PR title.
ℹ️
!`command` Syntax

The !`shell command` syntax inside a command file runs the shell command and injects its output into the prompt. This is how you pass dynamic runtime data (like git diffs) into your commands.

Essential Command Library

Here are production-ready commands for common developer workflows. Save these to .claude/commands/ and adapt as needed.

1. Conventional Commit

markdown — .claude/commands/commit.md
---
description: Stage all changes and create a conventional commit
allowed-tools: Bash(git add:*), Bash(git commit:*), Bash(git diff:*)
model: claude-haiku-4-5-20251001
argument-hint: [optional custom message]
---

<diff>
!`git diff --cached && git diff`
</diff>

Stage all changes and create a git commit with a Conventional Commits message.

Format: `type(scope): description`
Types: feat, fix, docs, style, refactor, test, chore, perf

If $ARGUMENTS is provided, use it as the commit message directly.
Otherwise, infer the best message from the diff.

Keep the description under 72 characters.

2. Security Audit

markdown — .claude/commands/security.md
---
description: Run a security audit on the specified path
allowed-tools: Read, Grep, Glob
argument-hint: [file-or-directory]
---

Perform a security audit on: $ARGUMENTS (or the entire src/ if not specified)

Check for:
1. **Injection** — SQL, NoSQL, command, XSS injection risks
2. **Authentication** — Broken auth, missing checks, weak tokens
3. **Authorization** — Missing access controls, privilege escalation
4. **Secrets** — Hardcoded credentials, API keys, tokens
5. **Dependencies** — Known vulnerable packages (check package.json)
6. **Input validation** — Unvalidated user input, type coercion risks
7. **CORS & Headers** — Misconfigured security headers

Report findings by severity: CRITICAL, HIGH, MEDIUM, LOW
Include file path and line number for each finding.

3. Feature Branch Workflow

markdown — .claude/commands/branch.md
---
description: Create a feature branch from main with standard setup
allowed-tools: Bash(git *)
argument-hint: <feature-description>
model: claude-haiku-4-5-20251001
---

Create a new feature branch for: $ARGUMENTS

Steps:
1. `git checkout main && git pull origin main`
2. Create a branch name from the description:
   - prefix with `feat/`
   - use lowercase kebab-case
   - max 40 chars
3. `git checkout -b [branch-name]`
4. Confirm the branch was created and output the branch name

4. Dependency Audit

markdown — .claude/commands/deps.md
---
description: Audit npm dependencies for security issues and outdated packages
allowed-tools: Read, Bash(npm audit:*), Bash(npm outdated:*)
---

Run a dependency audit:

1. Run `npm audit` and parse the output
2. Run `npm outdated` and parse the output  
3. Read package.json to understand which packages are used for what

Provide a prioritized report:
- **Critical/High security issues**: Must fix immediately
- **Outdated with breaking changes**: Review before updating
- **Outdated patch/minor**: Safe to update
- **Unused dependencies**: Candidates for removal

For each critical issue, suggest the specific fix command.

5. Test Coverage Report

markdown — .claude/commands/coverage.md
---
description: Run tests with coverage and identify under-tested files
allowed-tools: Bash(npm *), Read, Glob
argument-hint: [threshold: default 80]
---

Run the test suite with coverage:

1. Run `npm run test:coverage` (or `npm test -- --coverage`)
2. Parse the coverage results
3. Identify all files below $ARGUMENTS% coverage (default: 80%)
4. For the 3 most under-tested files, read them and suggest
   specific test cases that would improve coverage

Focus on testing business logic and edge cases, not just line coverage.

Sharing Commands With Your Team

Project-level commands in .claude/commands/ are committed to git and available to everyone on the team immediately. This is one of the highest-leverage things you can do for team productivity.

bash — Commit your commands
git add .claude/commands/
git commit -m "chore: add Claude Code commands for review, commit, security"

# Now all teammates can use /review, /commit, /security
💡
Start with These Commands

The highest-ROI commands for any team: /commit (consistent commit messages), /review (pre-PR self-review), /pr (PR description generation). These alone save significant daily effort.
