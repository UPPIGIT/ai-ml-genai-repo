01.2 Request · Response · Context
Request, Response & Flask Contexts
Request Object
from flask import request — thread-local proxy to current request
request.method: GET, POST, PUT, PATCH, DELETE, HEAD, OPTIONS
request.args: URL query string parameters (ImmutableMultiDict)
request.form: POST form data (ImmutableMultiDict)
request.json: parsed JSON body — requires Content-Type: application/json
request.data: raw bytes body when content type is unknown
request.files: uploaded files (ImmutableMultiDict of FileStorage)
request.headers: HTTP headers as dict-like object
request.cookies: cookie dictionary
request.remote_addr: client IP address
request.url, request.path, request.host, request.base_url
Response Object
make_response(): build explicit Response objects
Setting headers: response.headers['X-Custom'] = 'value'
Setting cookies: response.set_cookie(key, value, max_age, httponly, secure)
Deleting cookies: response.delete_cookie(key)
Status codes: return body, 201 or make_response(body, 404)
jsonify(): create JSON response with correct Content-Type
redirect(url, code=302): redirect to another URL
url_for(): generate URLs by endpoint name — reverse URL lookup
Flask Contexts
Application context (g, current_app): app-level state per request
Request context (request, session): request-scoped state
g object: store per-request data (DB connection, current user)
current_app proxy: access app config from anywhere
with app.app_context(): push context in scripts/tests
Context lifecycle: pushed before request, popped after response

Routing System — Complete
Route Definitions
@app.route(rule, methods=, endpoint=, strict_slashes=)
Multiple routes to one view: stack multiple @app.route decorators

Trailing slash rules: /about/ (canonical) vs /about (redirect or 404)
HTTP methods: methods=['GET', 'POST'] — default is GET only

URL Variables & Converters
<variable>: default string converter (no slashes)
<int:id>: integer converter — rejects non-integer URLs
<float:value>: floating point converter
<path:subpath>: string with slashes — matches full subpath
<uuid:uid>: UUID string converter

URL Building

url_for with query params: url_for('search', q='flask', page=2)

Error Handlers
@app.errorhandler(404): custom 404 Not Found page
@app.errorhandler(500): custom 500 Internal Server Error

abort(404): trigger HTTP error from any view function
HTTPException: catch-all for any Werkzeug HTTP exception
Custom error classes: inherit from HTTPException

11.1 Security · Performance
Security Hardening & Performance
Security Best Practices
CSRF: Flask-WTF CSRFProtect + validate_csrf for API AJAX calls
XSS: Jinja2 auto-escaping + Content Security Policy header
SQL injection: always use parameterized queries — never string concat
Secure cookies: SESSION_COOKIE_SECURE, SESSION_COOKIE_HTTPONLY, SAMESITE
Flask-Talisman: force HTTPS + set security headers (HSTS, CSP, X-Frame)
Input validation: validate on server — never trust client-side only
Secret key rotation: use secrets.token_hex(32) and rotate periodically
Dependency scanning: pip-audit or safety for known CVEs
CORS: Flask-CORS — whitelist origins, methods, headers explicitly
File upload security: validate MIME type, scan for malware
Performance Optimization
Query optimization: use .with_entities() to select only needed columns
N+1 problem: use selectinload() or joinedload() for relationships
Database indexes: add indexes on foreign keys and frequently filtered columns
Connection pooling: configure pool_size, max_overflow properly
Flask-Caching: cache expensive view and function results
Compression: Flask-Compress — gzip responses automatically
Profiling: Flask-Profiler, werkzeug ProfilerMiddleware, cProfile
Async views: async def view() with asyncio for I/O-bound operations
Gunicorn workers: worker_class=gevent for concurrent I/O
CDN: serve static assets from CloudFront/Cloudflare — not Flask
Logging & Error Monitoring
app.logger: built-in logger — use at INFO/WARNING/ERROR levels
Structured logging: loguru or python-json-logger for machine-readable logs
Sentry: pip install sentry-sdk[flask] — exception tracking and alerting
Flask-LogConfig: YAML/JSON logging configuration
Request ID middleware: attach unique ID for trace correlation

12.1 Gunicorn · Nginx · Docker
Production Server Stack
Gunicorn WSGI Server
gunicorn "app:create_app()": run Flask app in production
--workers: 2*CPU+1 sync workers, or gevent for async I/O
--worker-class gevent: concurrency for I/O-bound Flask
--bind 0.0.0.0:8000: bind to all interfaces
--timeout 30: kill stuck workers after 30 seconds
--access-logfile, --error-logfile: log configuration
gunicorn.conf.py: config file for all gunicorn settings
Graceful reload: kill -HUP PID — zero-downtime config reload
uWSGI: alternative WSGI server with more config options
Nginx Reverse Proxy
Nginx → Gunicorn via Unix socket or TCP port
proxy_pass http://127.0.0.1:8000: forward to Gunicorn
proxy_set_header: forward X-Real-IP, X-Forwarded-For, Host
client_max_body_size: increase for file uploads
Static files: Nginx serves /static directly — never hits Flask
SSL termination: Nginx handles HTTPS, Flask sees HTTP internally
Certbot: free Let's Encrypt SSL certificates auto-renewal
Gzip compression at Nginx level for all responses
Docker & Docker Compose
Multi-stage Dockerfile: builder stage + slim production image
Non-root user inside container — security best practice
docker-compose.yml: app + postgres + redis + nginx services
Health checks: check Gunicorn process is accepting connections
Environment variables via .env file and docker-compose env_file
Named volumes: persist PostgreSQL and Redis data
Network isolation: app network, internal DB network
