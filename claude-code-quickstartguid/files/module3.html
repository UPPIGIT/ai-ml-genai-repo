CLI Flags & Launch Options

The claude command accepts many flags that control behavior, model selection, and output format.

bash — Syntax
claude [flags] [prompt]
FlagPurposeExample
-p "prompt"Non-interactive: run one task and exitclaude -p "Write tests for auth.ts"
-cContinue the most recent conversationclaude -c
--resume <id>Resume a specific conversation by IDclaude --resume abc123
--model <m>Specify the model to useclaude --model claude-sonnet-4-6
--output-formatSet output format (text, json, stream-json)claude -p "..." --output-format json
--allowedToolsRestrict which tools Claude can useclaude --allowedTools Read,Grep
--max-turns <n>Limit agentic loop iterationsclaude -p "..." --max-turns 5
--no-toolsDisable all tools (chat only)claude --no-tools
--worktreeCreate isolated git worktree for this sessionclaude --worktree feature-auth
--versionPrint version numberclaude --version

Permission Prompts

When Claude wants to run a command or modify a file, it may ask permission. You can respond with:

Terminal interaction
Claude wants to run: rm -rf dist/
  [y] Allow  [n] Deny  [a] Allow always  [d] Deny always

# y / Enter  — allow once
# a          — allow this exact command always in this project
# n          — deny once  
# d          — deny this command always in this project

Built-in Slash Commands

Slash commands are typed during a session (starting with /) and provide quick access to session controls and features. Type /help at any time to see the full list.

CommandEffect
/helpShow all available commands (including your custom ones)
/clearClear the current conversation context and start fresh
/compact [hint]Summarize context to save tokens, retaining key info
/initGenerate a CLAUDE.md file for the current project
/model <name>Switch model mid-session
/bugReport a bug to Anthropic from within the session
/costShow token and cost usage for the current session
/statusShow session info, model, permissions
/doctorRun diagnostics on Claude Code configuration
/exitExit the session cleanly
💡
/compact vs /clear

Use /compact when context usage exceeds ~80% to summarize the conversation and free tokens while retaining important decisions. Use /clear when switching to a completely unrelated task where old context would be confusing.

Model Selection & Strategy

Claude Code can use different models. Choosing the right model balances capability, speed, and cost.

ModelBest ForSpeedCost
claude-sonnet-4-6 Most coding tasks — best balance (default recommendation) FastMedium
claude-opus-4-6 Complex architecture, multi-file refactors, deep analysis SlowerHigher
claude-haiku-4-5-* Simple lookups, quick questions, high-volume automation FastestLowest
bash — Selecting a model
# Start with a specific model
claude --model claude-opus-4-6

# Switch model mid-session
You: /model claude-haiku-4-5-20251001

# Use Haiku for a quick non-interactive task (cost-efficient)
claude -p "What does this error mean: ECONNRESET" --model claude-haiku-4-5-20251001
💡
Model Switching Strategy

Start complex sessions with Opus for architectural planning, then switch to Sonnet for implementation, and use Haiku for quick lookups or repetitive generation tasks. This optimizes cost without sacrificing quality where it matters.

Non-Interactive (Headless) Mode

The -p flag lets you run Claude Code without an interactive session — ideal for scripts, CI/CD, and automation.

bash — Headless examples
# Run a task and capture output
claude -p "Find all TODO comments in src/ and list them" > todos.txt

# JSON output for programmatic use
claude -p "Analyze package.json for outdated deps" \
  --output-format json > analysis.json

# Restrict tools for safety in automated contexts
claude -p "Review this code for security issues" \
  --allowedTools Read,Grep,Glob \
  --max-turns 3 > security-report.txt

# Pipe code into Claude
cat src/utils.ts | claude -p "Explain what this code does"

# Use in a shell script
#!/bin/bash
FILES=$(git diff --name-only HEAD~1)
claude -p "Review these changed files for bugs: $FILES" --allowedTools Read,Grep

JSON Output Format

bash + JSON output
claude -p "List all React components in src/" \
  --output-format json | jq '.result'

# JSON output includes: result, cost, tokens, duration
{

Session Management

Claude Code saves conversation history so you can resume exactly where you left off.

bash — Session control
# Start a new session
claude

# Continue the most recent session
claude -c
Resuming conversation from: "Implement user avatar upload..."

# List recent sessions
claude --list-sessions
abc123  2025-03-15  "Refactor auth module..."
def456  2025-03-14  "Add avatar upload feature..."
ghi789  2025-03-14  "Fix cart discount bug..."

# Resume a specific session by ID
claude --resume abc123

Conversation Context Tips

  • Long sessions consume more tokens — use /compact to compress context when it gets large
  • Sessions are stored in ~/.claude/conversations/
  • Context resets on /clear but the session ID remains for history purposes
  • For unrelated new tasks, starting fresh (/clear) often gives better results

Permissions & Safety

Claude Code has a fine-grained permission system so you control exactly what it can do.

Permission Levels

ModeDescription
Interactive (default)Asks permission for potentially destructive actions
--allowedToolsOnly specific tools are available (whitelist)
--no-toolsNo file access or commands — chat-only mode

Configuring Permanent Permissions

json — .claude/settings.json
{
  "permissions": {
    "allow": [
      "Bash(git *)",       // Allow all git commands
      "Bash(npm test)",    // Allow running tests
      "Read",             // Allow all file reads
      "Write(src/**)"     // Allow writes only in src/
    ],
    "deny": [
      "Bash(rm -rf *)",   // Never delete recursively
      "Bash(curl *)"      // No external requests from shell
    ]
  }
}

Effective Prompting Patterns

How you phrase requests significantly impacts Claude Code's effectiveness. Here are the patterns that consistently produce the best results.

Be Specific About Scope

Good vs. vague prompts
❌ Vague (leads to guessing)
"Fix the bug"

✓ Specific (gives Claude exactly what it needs)
"The user login fails when the email contains a + character.
 The error is in the logs: 'Invalid email format'. Fix this in
 src/auth/validation.ts and add a test for this case."

Specify Constraints Up Front

Prompting with constraints
"Add a rate limiter to the /api/auth routes.
 Constraints:
 - Use the existing 'express-rate-limit' package (already installed)
 - Config must be in a separate file: src/config/rateLimiting.ts
 - Max 5 requests per minute for login, 20 for other auth routes
 - Write a test that verifies rate limiting works
 - Don't modify existing tests"

Break Large Tasks Into Steps

Iterative approach
# Step 1 — understand first
You: Read the payment module and explain how checkout works

# Step 2 — plan
You: Given that architecture, outline what changes are needed to add
     Apple Pay support. Don't code yet, just outline.

# Step 3 — implement
You: Implement step 1 of your plan (the backend Stripe integration)

# Step 4 — review
You: Run the payment tests and fix any failures

Reference Files Explicitly

File references in prompts
"Look at src/components/Button.tsx as the design reference.
 Create a similar Card component in src/components/Card.tsx
 following the same patterns for props, styling, and exports."
💡
The "Read First" Pattern

For complex changes, start with: "Read [file] and explain what you find, then we'll plan the changes." This ensures Claude has the right context before making any edits — a common cause of mistakes is acting without full understanding.
